# Calico BGP模式：跨节点Pod到Host转发流程

## 一、网络拓扑假设

```
Node A (192.168.1.10)          Node B (192.168.1.20)
┌─────────────────┐            ┌─────────────────┐
│ Host: 192.168.1.10│          │ Host: 192.168.1.20│
│ Pod: 10.1.1.0/24  │◄──BGP───►│ Pod: 10.1.2.0/24  │
│   (Pod A:10.1.1.10)│          │   (Pod B:10.1.2.10)│
└─────────────────┘            └─────────────────┘
```

---

## 二、跨节点Pod到Host转发流程

### Pod A → Host B（跨节点）

```
Pod A (10.1.1.10) @Node A → Host B (192.168.1.20) @Node B

[Node A端]
Step 1: Pod A发出ICMP请求
  - 源IP: 10.1.1.10
  - 目的IP: 192.168.1.20

Step 2: 查找Node A路由表
  - 目的: 192.168.1.20
  - 匹配: 192.168.0.0/16 via 192.168.1.1

Step 3: 转发到eth0，通过网关192.168.1.1发出

[网络传输]
  - 报文路由到Node B

[Node B端]
Step 4: Host B接收
  - 目的IP匹配本机

Step 5: 生成ICMP响应
  - 源IP: 192.168.1.20
  - 目的IP: 10.1.1.10

Step 6: 查找回程路由
  - 10.1.1.0/24 via 192.168.1.10 (BGP学习)

Step 7: 响应报文返回Node A

Step 8: Node A转交给Pod A

✓ Ping成功
```

## 三、若需经过网关转发

### 3.1 拓扑图

```
Node A (192.168.1.10)      Gateway (192.168.1.1)      Node B (192.168.1.20)
┌─────────────────┐       ┌─────────────────┐      ┌─────────────────┐
│ Pod: 10.1.1.0/24│◄─────►│  L3 路由器   │◄─────►│ Host:192.168.1.20│
│   Pod A:10.1.1.10│       │  (ToR Switch)  │      └─────────────────┘
└─────────────────┘       └─────────────────┘
```

### 3.2 网关所需能力

| 能力 | 说明 |
|------|------|
| L3路由能力 | 三层路由器，非纯二层交换机 |
| Pod CIDR路由 | 需知道Pod网段的路由（如10.1.1.0/24） |
| Host路由 | 需知道各个Node的Host IP路由 |

### 3.3 网关配置

**基础信息**

```
Gateway IP: 192.168.1.1/24
Node A: 192.168.1.10 (同一二层)
Node B: 192.168.1.20 (同一二层)
```

**方式一：静态路由**

```bash
# 启用IP转发
echo 1 > /proc/sys/net/ipv4/ip_forward

# Pod CIDR路由（通过对应Node转发）
ip route add 10.1.1.0/24 via 192.168.1.10
ip route add 10.1.2.0/24 via 192.168.1.20

# Host IP路由（直连网络）
ip route add 192.168.1.10 dev eth0
ip route add 192.168.1.20 dev eth0
```

**方式二：BGP配置（推荐）**

```bash
# Cisco交换机示例
router bgp 64512
 bgp router-id 192.168.1.1
 neighbor 192.168.1.10 remote-as 64512
 neighbor 192.168.1.20 remote-as 64512
 network 10.0.0.0/8
```

**方式三：静态路由+BGP混合（互为备份）**

| 模式 | 说明 |
|------|------|
| BGP优先 | 优于静态路由时使用BGP |
| 静态备份 | BGP失效时自动回退 |

**注意**：配置静态路由后可能导致BGP学习失败，建议二选一使用

### 3.4 流量路径

```
Pod A → Gateway (192.168.1.1) → Host B (192.168.1.20)

Step 1: Pod A发送ICMP到192.168.1.20
Step 2: Node A路由：192.168.0.0/16 via 192.168.1.1
Step 3: 报文发往Gateway
Step 4: Gateway路由：192.168.1.20 via 192.168.1.20
Step 5: Gateway转发到Host B
Step 6: 响应同路径返回
```

---

## 四、报文封装

| 场景 | 封装方式 |
|------|----------|
| Pod → Host (跨节点) | 无，直接路由 |
| Pod → Host (经Gateway) | 无，Gateway作为下一跳 |

**关键特性**：BGP模式下无额外封装

---

## 五总结

| 场景 | 路由来源 | 路径 |
|------|---------|------|
| Pod → 跨节点Host | 本机FIB | Node A → Gateway → Node B |
| 回程 | BGP学习路由 | Node B → Gateway → Node A |

**经Gateway转发条件**：Gateway需配置Host IP和Pod CIDR路由
