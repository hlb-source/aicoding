# Go Code Reviewer

## 功能描述

该技能用于按照 Go 语言最佳实践对代码进行审查，并补充测试代码以确保测试覆盖率大于80%。

## 工作流程

1. **代码审查**：
   - 检查代码是否符合 Go 语言最佳实践
   - 识别潜在的问题和改进点
   - **自动修改代码**：根据审查结果自动对代码进行优化和修复
   - **除非明确要求不能自动修改代码，否则按照review意见修改代码**

2. **测试补充**：
   - 分析现有测试代码
   - 识别测试覆盖不足的部分
   - 补充缺失的测试用例

3. **覆盖率检查**：
   - 运行测试并计算覆盖率
   - 确保覆盖率达到80%以上
   - 提供覆盖率报告

## 使用场景

- 当用户需要对Go代码进行审查时
- 当用户需要补充测试代码以提高测试覆盖率时
- 当用户需要确保代码符合 Go 语言最佳实践时

## 支持的语言

- Go（主要支持）
- 其他语言（根据需要提供审查）

## 审查标准

### Go 语言最佳实践规则清单

#### 1. 代码风格
- 遵循 Go 语言官方规范（使用 `go fmt` 格式化代码）
- 包名使用小写、简短、描述性的名称
- **变量遮盖**：
  - 不允许有变量遮盖（shadowing）的代码
  - 特别注意循环内部使用 `:=` 导致的变量遮盖问题
  - 对于函数参数的变量遮盖，必须强制修改
  - **自动修复**：如果发现变量遮盖的代码，技能会自动进行修复
- 导入包按标准库、第三方库、本地库顺序排列
- 函数和变量命名使用驼峰命名法
- 接口命名使用 `-er` 后缀（如 `Reader`, `Writer`）
- 常量使用全大写字母，单词间用下划线分隔
- 注释使用英文，清晰描述代码功能和设计意图

#### 2. 错误处理
- 使用 `errors.New()` 或 `fmt.Errorf()` 创建错误
- 错误信息应清晰、具体，包含上下文信息
- 避免在错误处理中使用 panic（除非是不可恢复的错误）
- 错误应向上传递，而不是在中间层吞掉
- 使用 `errors.Is()` 和 `errors.As()` 进行错误类型判断
- 对于公共 API，应返回具体的错误类型，而不是 `error` 接口

#### 3. 测试规范
- 测试文件命名为 `*_test.go`
- 测试函数命名为 `TestXxx`
- 表驱动测试应使用清晰的测试用例结构
- 使用 `testing.T` 进行断言和错误报告
- 测试应覆盖正常路径、边界条件和错误情况
- 模拟外部依赖使用 `gomock` 或其他模拟框架
- 集成测试应标记为 `// +build integration`

#### 4. 性能优化
- 避免在循环中进行内存分配
- 使用 `sync.Pool` 重用对象
- 对于频繁访问的数据，使用缓存
- 避免不必要的复制（使用指针或引用）
- 优化 I/O 操作，使用缓冲读取
- 合理使用并发（避免过度并发）
- 定期进行性能测试和基准测试

#### 5. 安全性
- 避免使用硬编码的密钥和密码
- 验证所有输入参数
- 防止 SQL 注入和 XSS 攻击
- 使用 HTTPS 进行网络通信
- 正确设置文件权限
- 避免使用过期的依赖库
- 定期进行安全扫描
- **内存泄露检查**：
  - 确保所有打开的资源（文件、网络连接、数据库连接）都有对应的关闭操作
  - 使用 `defer` 语句确保资源在函数退出时被释放
  - 避免循环引用导致的内存泄露
  - 定期使用内存分析工具（如 `pprof`）检查内存使用情况
  - 注意 goroutine 泄露，确保所有 goroutine 都能正常退出

#### 6. 指针与值的使用
- 对于大型结构体或需要修改接收者的情况，使用指针接收者
- 对于小型结构体和需要不可变性的情况，使用值接收者
- 当需要修改参数或处理大型结构体时，使用指针参数

#### 7. 接口设计
- 在使用接口的地方定义接口，而不是在实现接口的地方
- 除非必要，否则不要导出接口

#### 8. 并发编程
- **Goroutines**：
  - 在库中创建 goroutine 时要谨慎，最好让调用者控制并发
  - 确保所有 goroutine 都能正常退出，避免 goroutine 泄露
  - 使用 `context` 包管理 goroutine 的生命周期
- **通道**：
  - 使用无缓冲通道进行同步通信
  - 使用缓冲通道进行异步通信
  - 避免使用过大的缓冲通道，以免导致内存问题
- **互斥锁**：
  - 尽量减少锁的范围，只保护必要的代码区域
  - 避免嵌套锁，防止死锁
  - 考虑使用 `sync.RWMutex` 提高并发性能

#### 9. 代码组织
- 每个文件应专注于一个功能或相关功能组
- 函数应保持简短，通常不超过 50 行
- 避免过长的参数列表，考虑使用结构体传递多个参数
- 使用包级变量时要谨慎，尽量使用局部变量

#### 10. 文档
- 为公共函数、类型和包提供清晰的文档注释
- 文档应包括函数的用途、参数、返回值和使用示例
- 对于复杂的算法或设计决策，提供详细的注释说明

#### 11. 依赖管理
- 使用 `go mod` 管理依赖
- 定期更新依赖库，避免使用过期版本
- 明确指定依赖版本，避免依赖冲突
- 只导入必要的包，避免不必要的依赖

## 测试补充策略

- 单元测试：针对函数和方法的测试
- 集成测试：测试组件之间的交互
- 边界测试：测试边界条件和异常情况
- 模拟测试：使用模拟对象测试依赖关系

## 覆盖率计算

使用标准的测试覆盖率工具（如 Go 的 `go test -cover`）计算测试覆盖率，并确保覆盖率达到80%以上。

## 输出结果

- 代码自动修改：根据审查结果自动对代码进行优化和修复
- 测试补充：添加缺失的测试用例
- 覆盖率报告：当前覆盖率和改进建议
